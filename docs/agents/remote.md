# The file and git layer and the remote server (stages 1 and 2 of #20)

All access to the Root's files and git goes through `host::Host` (crates/antler-host/src/host.rs; read its doc comments for the contract). Two implementations: `Local` (this machine) and `remote::Remote`, which forwards each call to `antler-server` on the Remote host (docs/adr/0005). Stage 3 (done) starts the server over SSH (`src/ssh.rs`), keeps it alive as a daemon, reconnects and adds the Remote window (`src/remote_view.rs`).

## Crates
- `crates/antler-host` (library, no UI; meant to build on Linux, macOS and Windows): `host` (trait, `Local`, `remove_all`), `discovery` (Nested repository walk), `search` (`ignore` walk, `grep` matcher, `replace`), `exclude` (`files.exclude`), `protocol`, `remote` (client), `server` (the serve loop). Trash through objc2 is `cfg(target_os = "macos")`; elsewhere `Local::trash` deletes for good.
- `crates/antler-server`: the binary, `serve(stdin, stdout)`. Nothing else may print to stdout.
- The app (`src/`) keeps its module paths: `crate::host`, `crate::discovery`, `crate::search` re-export the library; `search.rs` also holds `SearchJob` / `ReplaceJob`.
- `cargo test --workspace` runs everything. `ANTLER_TEST_REMOTE=1 cargo test` runs the whole model suite through a spawned `antler-server` (the four tests of undoing a Trash skip themselves: a remote has none). `workspace/tests_remote.rs` and `crates/antler-server/tests/remote.rs` always run.

## Rules for new code
- A file or git access under the Root goes through the Root's host, never `std::fs`, `Command::new("git")` or `notify`.
- Calls are blocking, from background tasks, coarse (one call, whole result).
- The host belongs to the Root: `Workspace::host`. Jobs (`ScanJob`, `SearchJob`, `ReplaceJob`, `SaveJob`, `FilesJob`) carry it to their thread. Code below a job that has no host parameter (git.rs, the ops, the loaders) calls `host::current()`, which is the host of the enclosing `host::scoped(&host, || ...)`; outside any scope it is `Local`. A new `background_spawn` that touches files or git must wrap its body in `host::scoped(&self.ws.host, ...)`; a quick check on the UI thread uses `self.host` directly. Never cache `current()` across jobs.
- Settings, recent, keys, state, windows, update and askpass are not the Root's: they stay on `std::fs`.
- `git.rs` `diff_texts` writes temp files here and runs git on `host::local()`, whatever the Root's host.

## Protocol (`protocol.rs`)
- Transport: the server's stdin (requests) and stdout (answers); stderr is the server's log.
- Frame: `u32 header_len | u32 body_len` (big endian), a JSON header, a raw body. Why: the header stays readable in a captured stream and serde_json is already a dependency, while file bytes (any bytes, up to the 1 GiB limit) travel raw instead of through base64 (+33 %, an extra copy). No new dependency.
- First frame: the server's `Hello { protocol, os, arch }` (id 0). The client refuses another `VERSION`.
- Requests carry an `id`; answers carry the same id and may arrive in any order (a thread per request on the server), so several are in flight. One request per `Host` method, plus `Cancel { target }`.
- Streams: `Watch` is answered by `Ok`, then `Event { path }` frames with its id until `Cancel` (the client's `WatchGuard` drop). `Search` is one answer with the whole `Results`; its `Cancel` makes the server stop the walk early and answer with what it has (the client sends it as soon as the `cancel` flag is set). Search results are not streamed: the `Host` contract returns them whole.
- Errors: `Err { kind, msg }`; `kind` is an `io::ErrorKind` name (`NotFound`, `AlreadyExists`, `PermissionDenied`...) so the model's `kind()` matches work; empty for text errors (git, watch).
- `files.exclude`: the client sends the app's current patterns with `ListDir`, `Files` and `Search`; the server builds a `Local::with_exclude` per request (it has no settings).
- Trash: `Req::Trash` deletes for good; `Remote::trash` returns `Ok(None)`, so `Op::Trash` has no undo (the confirmation is the caller's).
- Lost connection: the reader thread ends, every waiting call fails with `ConnectionAborted`, new ones fail at once; `exists` is `false`, scans are empty, `search` has `error`. A supervised `Remote` then reconnects (stage 3, below).

## Paths on a Windows host
- On the wire a path is a string with `/` separators, drive included (`C:/Users/x`), made by `protocol::wire_path` and read by `native_path` (which puts the backslashes back on Windows). Nothing else changes: the app keeps `Path`/`PathBuf`, and `join`, `parent`, `file_name`, `strip_prefix`, `starts_with` work on `C:/Users/x` on a Mac. Windows accepts `/`.
- What the app model still assumes: the Root is a path the *server* gave or accepted, never `canonicalize`d, `is_absolute()`ed or `is_dir()`ed on the Mac (`main.rs` does that to the folder being opened: Remote windows must skip it); names are UTF-8 (lossy otherwise); no UNC (`\\server\share`) paths (`shortcut:` in `protocol.rs`). A file name with a backslash on a Unix host is fine (only a Windows server converts). Git on a Windows host reports paths with `/`, like on Unix.
- Not compiled here: the Windows branches (`Local::rename`'s case-only check, `copy` of links) and the Linux target were written blind; no Linux or Windows target is installed. Check them in stage 5's CI.

## Stage 3: SSH, delivery, daemon, reconnect, Remote window
- **Connection** (`src/ssh.rs`, `SshConnector`): the system `/usr/bin/ssh` (`ANTLER_SSH` replaces it, for tests) with `ControlMaster=auto`, `ControlPersist=10m`, `ControlPath=/tmp/antler-ssh-<pid>-<n>/%C` (an owner-only folder; `/tmp` because a unix socket path must stay short), `ServerAliveInterval=15`, `ConnectTimeout=30`, `BatchMode=no`. Passwords, passphrases and the host key question go through `SSH_ASKPASS` = the antler binary (`git::askpass_envs`, `SSH_ASKPASS_REQUIRE=force`): an osascript dialog. Zed does the same with the system `ssh` (`crates/remote/src/transport/ssh.rs`: `ControlMaster=yes`, `ControlPersist=no`, its own `ControlPath`, `SSH_ASKPASS` + `SSH_ASKPASS_REQUIRE=force`); only ideas were taken. `ANTLER_SSH_CONFIG` replaces `~/.ssh/config` (hosts list and `-F`).
- **Delivery**: `uname -sm` + `$HOME` (no `uname`: Windows, `PROCESSOR_ARCHITECTURE` and `USERPROFILE` through `cmd` or PowerShell); the server lives in `~/.antler-server/<version>/antler-server[.exe]`, so another version is another file (a mismatch installs the right one; the protocol `VERSION` is checked too). Missing: the Mac takes the asset `antler-server-<version>-<os>-<arch>[.exe]` (os `linux|macos|windows`, arch `x86_64|aarch64`) from `https://github.com/gianmadd/antler/releases/download/v<version>/` into `~/Library/Caches/Antler/server/` (with `curl`) and uploads it over the same ssh (`cat > tmp && chmod +x && mv`; PowerShell with `-EncodedCommand` on Windows). `ANTLER_SERVER_BINARY=<path>` installs a local file instead (for development). Unix commands are one `sh -c '…'` word, so any login shell takes them.
- **Daemon and proxy** (`crates/antler-server/src/daemon.rs`): `antler-server proxy` is what each connection runs; it attaches to `antler-server daemon` or starts it (detached from the ssh session). The daemon listens on `127.0.0.1` with a random port and a random token written to `<base>/<version>/daemon` (owner-only), on every OS: loopback TCP is the smallest thing that also works on Windows (no named pipe, no cfg). It runs `serve` per connection (several windows may share it) and exits after 3 h with no client (`ANTLER_SERVER_GRACE_SECS`, `ANTLER_SERVER_DIR` for tests). The protocol is unchanged. Watches die with the connection and are sent again by the client; nothing else is server state. Port forwarding (stage 4) can use the same connection.
- **Reconnect** (`remote.rs`, `reconnect.rs`): `Remote::open(connector)` connects once, `Remote::lazy` not yet; `supervise(on_status)` retries a lost connection with VS Code's waits (0, 5, 5, 10 ×5, then 30 s) until 3 h have passed, reports `Status::{Connected, Reconnecting, GaveUp}`, and sends the active `Watch`es again (same ids). Calls during the loss fail with `ConnectionAborted`; the window skips `refresh` while disconnected (a scan would find nothing and empty the panels) and refreshes on `Connected`. Unsaved text lives in the app. `retry()` (Reload Window) starts a new grace time.
- **Remote window** (`remote_view.rs`): `Antler::remote: Option<RemoteWin>`; Connect to Host… = host picker, `Remote::open` + `host_info` in the background, folder picker (`list_dir` from the host's home), then `new_remote_window`. A window is saved as `WindowSave { host, root, .. }` and reconnects lazily at start (layout restored on the first `Connected`). The Registry knows the host (the same path on two hosts is two folders). Skipped for hosts: `canonicalize`, `is_dir`, recent folders.
- **UI-thread checks left, accepted** (a round trip each; a connection that is dead but not yet noticed blocks them until `ServerAliveInterval` gives up, about 45 s): `check_name`, `drop_entries` / `copy_target`, `Workspace::resolve`, `restore_layout` (a call per file), `ImageTab::load`. Move to jobs if it bites.
- Not tested here: a real `ssh` connection (Remote Login is off on the dev Mac; the tests use a stand-in `ssh` that runs the command locally), Windows and Linux hosts, ControlMaster behaviour, the GUI flow of the picker.

## Still open
- git credentials: `Envs` (askpass, `osascript`) are local UI; a remote git needs its own path. The envs are forwarded as given.
- `Remote::search` / `files` copy the whole result per call; big Roots may want paging.
- The server starts a thread per request without a limit, and a `Cancel` that arrives before its `Watch` thread has stored the guard leaves the watch running until the connection closes.
- Two proxies started at the same instant may start two daemons (the later file wins; the other leaves after its grace time).

## Stage 5: release assets

- `release.yml` builds the app zip (job `app`) and `antler-server` (job `server`, matrix on native runners) for linux x86_64/aarch64 (musl, static), macos x86_64/aarch64 and windows x86_64/aarch64 (msvc), named `antler-server-<version>-<os>-<arch>[.exe]`. Job `publish` (tags only) downloads every artifact and runs `gh release create` once; a manual dry run only keeps the artifacts.
- The server is built with `cargo build --profile server -p antler-server` (`[profile.server]` in `Cargo.toml`: `opt-level = "z"`, lto, `panic = "abort"`, strip); the app keeps `release`.
- `ci.yml` runs `cargo check -p antler-server` for a Linux musl and a Windows msvc target on every PR/push, so the branches written on a Mac do not rot. Locally: `rustup target add <triple>` then the same check.
- `scripts/release.sh` verifies all assets are in the release before updating the cask.
