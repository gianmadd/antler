# Differences from VS Code

Antler copies VS Code's Explorer and Source Control; for git, ADR 0003 applies ("behave like VS Code with default settings"). This file lists the **deliberate** differences. Anything still missing is tracked as a parity gap in the issue tracker.

| Area | VS Code | Antler |
|---|---|---|
| Nested repositories | scan up to `git.repositoryScanMaxDepth` | same limit (default 3), plus: repos inside folders ignored by the parent repo, Linked worktrees labelled "worktree of …", `.venv*` folders skipped |
| Section header | name; branch in the status bar or in the Repositories view | name + branch in grey next to it; no Repositories view |
| Diff | side by side by default (inline below 900 px), right side editable, stage of selected lines; gutter bars with quick diff | side by side by default, inline below 900 px; the right side of the Changes diff is editable only side by side (inline, Staged Changes and commit diffs are read-only; the editor has no view zones to draw removed lines in an editable inline view); the two halves scroll together line by line, with no filler blank lines (a changed line faces the removed one, extra additions stay without a counterpart; the editor cannot insert blank space between lines); Stage, Unstage and Discard Block act on one change, so two nearby changes are two Blocks; gutter bars, Stage/Discard Block and Stage/Revert Selected Ranges work on the text in the editor, saved or not; a revert edits the text (one undo step, whole changes at a time) and then saves, with no confirmation, as VS Code does; Unstage Selected Ranges only in the Staged Changes diff, where VS Code has it too |
| Graph | current branch + upstream ("Auto" filter), Auto / All / branch picker; the choice is saved per repo and survives a restart | same; saved in `~/.config/antler/state.json` (`graph_filters`, `"all"` or a list of refs, Auto not saved) instead of VS Code's per-workspace storage, so it is per repo path, whichever folder is open |
| Actions on Graph commits | Checkout (Detached), Create Branch…, Create Tag…, Cherry Pick, Compare with Remote / Merge Base / Ref…, Copy; "Force Checkout" discards all changes, untracked files included (to the Trash), then checks out | same, but no Compare entries: they open a multi-file diff editor between two refs, which Antler has no view for; Esc on the tag message box cancels the tag (VS Code still creates a lightweight one) |
| Branch | branch name in a box at the top, with the live "Branch … already exists" / "The new branch will be …" line; "Stash & Checkout" / "Migrate Changes" ask for the stash message | same, also for Rename Branch…; no `git.branchPrefix`, random name or validation regex, which are off or empty in VS Code's defaults |
| Auto save | `off` by default | on by default after 0 ms |
| Markdown preview | new tab or side by side | in the same tab, eye button / Cmd+Shift+V |
| Typing in the Explorer tree | jumps to the row (`typeNavigationMode`); the find box at the top right highlights and jumps, with ↑/↓/Enter, Esc closes it; the Filter button switches to filtering | same as VS Code with find highlighting (default `find`); the filter stays behind the Filter button and applies only to rows already loaded. Every letter opens the find box, without Cmd+Alt+F |
| Settings | UI + JSON, `settings.json` with every VS Code setting | Settings tab (⌘, or the gear in the Activity bar) with search and categories, over `~/.config/antler/settings.json`, which can be edited by hand and is reloaded within a second; only the settings listed in the tab exist. VS Code's names where VS Code has the setting, `antler.` otherwise (ADR 0004). `files.exclude` matches file names only (last path segment, `*` wildcard) and is a comma-separated text field in the tab; the minimap, `update.mode` and the dialogs' "don't ask again" choices write the same file. `editor.fontFamily` is empty (the theme's monospace font), `editor.fontSize` 13; `window.restoreWindows` is only `all` / `none`; `antler.uiFontSize` resizes the stock components, text with a fixed size in Antler's own panels keeps it; `files.autoSave` is `off` / `afterDelay` only |
| Moving onto an existing name (drag, Cut/Paste) | asks whether to replace | refuses with an error, both files stay |
| Windows | one app, several windows, reopening | same (⇧⌘N, ⇧⌘W, ⌘`, Window menu, Open Folder replaces the folder). Not there: a window has no title other than its folder name, and `antler --depth N` flags only apply when the app starts (a running app ignores them). A folder opened from outside (Finder, Dock) at start leaves the restored/empty window beside it |
| Theme | any installed color theme, `workbench.colorTheme`, follows the OS with `window.autoDetectColorScheme`; file icon themes, `workbench.iconTheme` | built-in Antler Dark / Antler Light (VS Code's Dark Modern / Light Modern colours with the Amber accent); Color Theme picker with live preview on ⌘K ⌘T; the syntax colours are approximations of Dark+ / Light+ for tree-sitter; font 14. Themes install from a `.vsix` (Install Theme from VSIX…, extracted to `~/.config/antler/themes/`; no marketplace, "Get more themes" opens Open VSX). A VS Code colour theme is mapped onto Antler's palette (UI colours the palette has no key for are ignored) and its TextMate `tokenColors` onto tree-sitter highlight names (approximate); semantic token colours and product icon themes are not read. Icon themes: Seti built in (the default, like VS Code) and None; SVG/PNG and `.woff`/`.ttf`/`.otf` font definitions (not WOFF2); File Icon Theme picker has no default key; `languageIds` use a built-in extension to language table; `hidesExplorerArrows` is ignored; no icon in the Settings and no root-folder icons |
| Zoom keys | ⌘= / ⌘- zoom the whole window, ⌘0 focuses the side bar | ⌘= / ⌘- / ⌘0 change and reset the editor font size, like Zed |
| Keybindings | `keybindings.json` with `when` expressions, comments allowed | `~/.config/antler/keybindings.json`, same `[{ key, command, when }]` and `-command`, reloaded within a second of saving; plain JSON (no comments), `when` is one of `input`, `editor`, `explorer`, `git`, `search`, `commit` (unknown ones are ignored with a warning); command ids are VS Code's where VS Code has the command |
| Editor groups | any number, split in four directions, drag a tab to an edge; layout, sizes and all tabs restored | right and down only (`workbench.action.splitEditor` is "Split Editor Right"); a drag to any edge makes a group; only a layout with a split is restored (its groups and their files, no sizes: every split starts equal), a single group is not; closing the last tab of a group removes it. Settings opens once, in the group it was opened in, and cannot be split. Two views of one file share the text and its edits, not the cursor, selection, scroll or undo history. Split Editor Orthogonal (⌘K ⌘\\) and the group keys ⌘1…⌘8 are VS Code's; Split Editor Down has no key (as in VS Code), nor Focus Next/Previous Group |
| Staged/Changes groups | collapsible | not collapsible (to be aligned) |
| Remote - SSH | Remote Explorer, `remote.SSH.*` settings, remote extensions, terminal, `remote.SSH.configFile` | Connect to Host… (File, gear, palette, the status-bar item) over the system `ssh`; hosts from `~/.ssh/config` (`Host` entries without wildcards, `Include` followed) or `user@host[:port]`; the folder picker lists folders only and is not a free path field (no typed paths yet). No `Match` handling, no list of recent hosts or folders, no Remote Explorer, no settings (`ANTLER_SSH_CONFIG` replaces the config file; `ANTLER_SSH`, `ANTLER_SERVER_BINARY` are for development). The server runs as a daemon for 3 hours after the last connection and the app retries with VS Code's schedule; the dialog after that has Reload Window and Close. The window title is `folder [SSH: host]`; the indicator is bottom-left. A restored Remote window reconnects at start. Deleting is permanent (no Trash), like VS Code |
| Server delivery | the host downloads the server itself (`remote.SSH.localServerDownload` default: host first, the Mac downloads and copies it only if that fails) | the Mac always downloads the server for the host's OS/arch from the release and copies it over SSH: the server is ~2–3 MB (VS Code's is tens of MB with Node.js), so this costs seconds once per version and works on hosts without internet |
| Ports view | a table with Port, Forwarded Address, Running Process, Origin, Visibility, Label; many more attributes (`remote.portsAttributes`, `remote.restoreForwardedPorts`, Make Public, protocol, Preview in Editor) | Activity bar view only in Remote windows, one two-line row per port (the address is a link that opens the browser; the second line has the host's address, process and origin: a 320 px panel has no room for four columns); actions in the row's menu and the + button: Forward a Port, Stop Forwarding Port, Open in Browser, Copy Local Address. `remote.autoForwardPorts` and `remote.otherPortsAttributes.onAutoForward` (`notify`, `openBrowser`, `silent`, `ignore`) only; no `portsAttributes`, labels, `remote.localPortHost` (always `localhost`, only `127.0.0.1` is bound). A port already listening when the window connects is not forwarded. Only the ports the user forwarded come back after a restart (not the auto-forwarded ones, which are forwarded again if the host starts them again). The status bar count appears only when there is at least one forwarded port. Forwarded through the app's own connection, not `ssh -L`; the host side connects to `localhost`, so a service bound to one non-loopback address only is not reachable |
| Windows (#40) | settings in `%APPDATA%\Code\User`; Ctrl keys; menu bar in the title bar; Delete to the Recycle Bin; one running instance (a second `code` opens its folder in the first) | settings, keybindings, state and themes in `%USERPROFILE%\.config\antler` (the same `~/.config/antler` as on the Mac); VS Code's Windows default keys (Ctrl for Cmd; F2, Delete, F3, Ctrl+H, Ctrl+K Ctrl+O, Ctrl+PageDown… where VS Code differs), no keys for Minimize and Next Window; GPUI's menu bar in the title bar, the Mac app menu's items under File > Preferences and File > Exit, a two-chord key shows only its first chord there; Delete goes to the Recycle Bin with no Undo (the shell gives no location back); each `antler.exe <folder>` is its own process (no single instance yet); with no ControlMaster each SSH step is its own connection, but the password is asked once per host and kept in memory until Antler quits (the askpass broker) |

Excluded by choice: integrated terminal, extensions, AI-generated commit messages.
